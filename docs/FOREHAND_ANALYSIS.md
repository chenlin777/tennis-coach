# 正手辅助手复看试验版

这项功能寻找“挥拍附近，辅助手偏低或提前下落”的候选时间点，帮助教练把注意力放到值得慢放检查的位置。它按项目教练“辅助手保持抬起、帮助指向来球，击球时向后收”的经验开始试验，目前能够筛选的是手腕高度和运动顺序。

每条提示带有时间依据和复看建议；画面无法支持判断时保留缺失。当前不提供综合技术评分，候选仍需要结合视频和练习情境判断。

## 启动与使用

需要 Python 3 和近期版本的 Edge 或 Chrome，无需显卡或 Python 机器学习环境。

1. 首次运行 `setup-auto.cmd`，下载并校验本地模型与浏览器运行库。隐私处理已经安装过同一套资源时，无需再安装。
2. 双击 `start-coach.cmd`，保持启动窗口运行。也可以执行 `python serve.py --page forehand --open`；端口被占用时加上 `--port 8766`。
3. 选择本机视频。建议使用原速、连续正手练习的 10–20 秒片段，最长 60 秒；更长的视频可先拖到 `prepare-clips.cmd` 剪辑。
4. 选择球员实际使用的持拍手，以及片段内容。只有已确认左右手的“连续正手练习”才会生成动作候选。混合正反手、自抛球或信息未选全时，可以查看姿态与需复看的位置。
5. 如果视频经过左右镜像，勾选对应选项。它影响持拍手和辅助手的对应，不翻转显示画面。
6. 有旁观者或画中画时，请暂停，在“选择分析人物”模式中点击击球者的躯干，建议选择片头人物清楚的时刻。也可用方向键移动十字，按回车确认。人物点选发生在当前视频时刻，需要核对叠加的关键点是否跟对人；自动选择可能选中解说员或其他大幅人物。
7. 点击“分析辅助手”。完成后，点击候选时间或证据按钮跳到画面，使用半速或四分之一速度复看。黄色显示辅助手相关点位，绿色显示其他身体点位；缺失点位不补画。
8. 如需保存结果，点击“导出初步报告 JSON”。退出时关闭服务窗口。

页面完成一次姿态采样后，会在当前页缓存该视频的结果。修改持拍手、练习场景、镜像或人物选择，会立即复用姿态重新筛选；无需重复运行模型。分析过程中改变这些信息会取消旧任务，需要重新开始。换视频也会清除旧结果，防止报告错配。

隐私处理导出的 WebM 有时没有记录视频时长。页面会先在本机读取结尾、确认实际长度，再返回开头；确认超过 60 秒时仍须先剪辑。

预览的半速与四分之一速度只影响观看，不改变已完成的分析。原片本来就是慢动作时，模型看到的动作时长也被拉长，当前规则可能漏掉动作；应优先选择原速素材。

## 结果怎样理解

| 页面结果 | 可以据此做什么 |
| --- | --- |
| 发现候选 | 慢放核对辅助手的位置及所处阶段，排除随挥后放松、人物识别错误等情况。 |
| 未检出候选 | 继续按需要复看原片；没有提示不代表动作合格，也不能证明没有漏报。 |
| 画面不足 | 检查遮挡、人物大小、是否出画、选人位置和关键点是否跟错。 |
| 需要确认持拍手或场景 | 补充正确设置；混合动作和自抛球暂时只用于姿态复看。 |

“可用姿态比例”统计当前跟踪对象在采样画面中的可用情况，不能作为动作合格率。关键点的模型置信度也不是“这项教学判断正确”的概率。

点选人物后仍可能跟错。多人交叉或长期跟踪中断时，规则保留需要人工复看的区间；可换一个清楚的时刻重新选人，或者剪成更短、更连续的片段。

## 方法与适用范围

姿态提取使用本地 MediaPipe Pose Landmarker Lite，默认按每秒 12 帧采样，通过 WebAssembly 在 CPU 上运行。模型提供人体关键点；Web API 和输出坐标的说明见 [MediaPipe 官方文档](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)。本项目仅用二维图像位置进行候选筛选，没有将模型的三维输出当作真实生物力学测量。

规则先检查目标人物的肩、肘、腕和髋是否可靠可见，再以躯干在画面中的尺度归一化手腕位置，结合短时间内辅助手下落、持续偏低与持拍手上挥的顺序筛选候选。它尝试排除随挥之后的自然放松。阈值是待校准的工程设置，尚不是教练确认的教学标准。

当前不识别来球、球拍、触球时刻或真实视线，也不能确认辅助手是否准确指向球、向后收肘的方向与时机是否正确。提示中的“前挥／上挥候选”是二维运动迹象，不是已确认的击球阶段。

适合先尝试肩、肘、手腕和髋部清楚入镜的连续正手片段。人物过小、运动模糊、手臂遮挡、频繁切镜、多人交叉和侧身透视都可能造成误报、漏报或无法判断；打码如果盖住相关关节，也会影响结果。人物静止、辅助手放松或手腕偶尔偏低本身不构成技术错误，仍须结合完整动作。

## 报告、标签与本地数据

报告标记为 `candidate_review`，并包含 `requiresCoachReview: true`。它记录文件名、大小、修改时间、视频尺寸与时长、模型和规则版本、当前设置，以及候选和证据时间。当前文件对应依赖这些元信息，不包含内容哈希核验；文件名相同不保证内容相同。

浏览器导出报告、助手查看视频形成的六项初标、教练确认标签是不同记录。报告不会自动写入数据集标签，也不会把候选转成“需改进”的教练结论。公开素材的助手初标尚待复核，不作为已确认的训练答案或评测真值。

视频通过浏览器文件选择器在本机读取，原文件不修改。运行时只请求本机静态资源，没有视频上传接口。导出的报告保存在用户选择的位置；需要放回项目时，请保存在被 Git 忽略的 `local/` 中。

## 验证与下一步

现有自动检查覆盖二维规则的代表性序列，以及页面取消、旧结果隔离、设置变化、人物选择、慢放定位和报告来源信息。合成序列与模拟姿态用于检查程序行为，不能衡量真实视频的识别准确率。

### 首批真实视频检查（2026-09-26）

已检查 9 个原始来源的 9 段视频，其中开发用 5 段、留出检查 4 段，共 1,444 个采样画面。当前全部未生成辅助手候选，尚未证明能检出真实技术问题，不能据此称为可用的自动教练。

暴露出的主要问题是辅助手腕和肘部遮挡、模型置信度不足，以及多人或画中画场景的目标选择。两个待教练确认的辅助手下落窗口，分别只有 8/24 和 0/25 个采样画面可用，关键时刻的证据不足。一段画中画视频自动跟到了讲解者；改为点选击球者后，仍未取得可靠的动作证据。可用姿态比例不能代替跟踪对象正确性，更不能代替教学判断准确率。

混合动作和自抛场景按设置抑制了技术候选；慢动作参考片没有出现等待或恢复阶段的提示。这些结果用于检查当前行为，不构成误报率或漏报率结论。助手初标仍未作为评测真值。

实际页面在一个 15 秒视频上约用 13.73 秒完成分析，导出报告和修改设置后的缓存重算正常；该次检查没有页面错误或外部网络请求。耗时仅代表当次本机运行，不是跨设备速度保证。

接下来对真实视频逐项记录：人物是否跟对、候选是否有画面依据、误报来自哪个阶段、哪些动作漏掉、哪些视频无法判断。先用少量代表性片段校准教练意图，再在未参与调试的不同来源视频上检查；教练未确认的初标继续作为待复核记录保存。
