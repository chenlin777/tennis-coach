# 开发路线

## 分工

教练负责教学判断：问题是否存在、为什么优先处理、建议是否合适，以及实际训练中是否改善。

开发工作负责把这些判断整理成规则与数据结构，制作视频工具，接入模型，测试并维护 GitHub 项目。教练可以用自然语言或口述提供案例。

## 已有原型：本地隐私预处理

上传前处理隐私是第一项产品需求。当前已有本地视频预览与自动头脸遮盖，结合人脸检测、姿态跟踪和时间轴关联，使遮盖框随运动变化。支持手动补充固定区域、环境保留框外像素化，以及全部不处理。导出静音副本，原片留在本机。

自动模式会提示没有检测结果的时间段，但不能发现所有漏遮；目前也存在背景、手臂被多遮的问题。后续优先改善误检筛选与按时间段修改遮盖框，再考虑保留球、球拍和地面参照的环境分割。当前没有自动环境分割，也没有教学动作评分。完整预览和人工修正仍是必要环节。

说明与边界见 [隐私处理说明](PRIVACY.md)。

## 当前试验：正手辅助手候选

已接入本地 Pose Landmarker Lite，以每秒约 12 帧采样肩、肘、腕和髋位置，按二维时序规则寻找挥拍附近辅助手偏低或下落的候选。`start-coach.cmd` 提供视频选择、持拍手和场景设置、可选人物点选、关键点叠加、慢放定位及 JSON 报告。模型在浏览器 CPU 上运行，视频不上传。

这是里程碑 3 的姿态辅助和里程碑 4 的规则试验入口。候选报告与助手查看视频形成的初标、教练确认标签分开；当前规则没有识别球、触球时刻或完整击球阶段，也没有完成自动教学评分。使用说明见 [辅助手复看说明](FOREHAND_ANALYSIS.md)。

首批 9 段真实视频检查全部未检出候选；关键窗口的腕肘证据不足，画中画场景也暴露了自动选错人的问题。当前已验证流程可以运行，真实问题检出仍未通过验证；下一轮应先处理这些观测限制。

下一步围绕同一教学问题检查误报、漏报和无法判断的原因。先核对代表性片段是否还原教练的意思，再用不同来源、未参与调试的视频检验规则；逐渐补充难例和例外。公开影片上的助手初标可用于准备复核，未经教练确认不能当作评测真值。

## 里程碑 1：一份完整的真实案例

已经有本地原片归档、10–20 秒左右的切片、来源索引、教学标签和助手初标复看页。下载器可以处理单视频 URL 并记录失败；是否能获取仍取决于平台访问条件。自有视频与已收集的外部素材分别记录来源和使用条件，并按机位、可见性和训练情境保留差异，见 [数据集流程](DATASET.md)。

输入：一段教练熟悉、全身和球拍尽量清晰的正手视频。先选一个教练最常处理的问题。

产物：视频时间点、观察事实、判断理由、优先级、练习建议、适用条件和改善标准。

完成条件：教练确认记录准确表达了自己的思考；缺失信息与暂不确定的部分明确保留。

入口：[教学案例模板](COACHING_CASE_TEMPLATE.md)。真实记录保存在被 Git 忽略的 `local/coaching-cases/`。

## 里程碑 2：可运行的视频复盘原型

已有本地页面支持打开视频、慢放、定位证据时间和展示既有标签。后续加入方便教练修改和保存案例的入口，按实际复核流程决定界面需要展示什么。

完成条件：教练能在同一个界面里指明证据并修正记录；保存后可以重新打开。

## 里程碑 3：姿态识别辅助

已有辅助手复看页面展示姿态关键点和候选时间。继续用真实视频检查遮挡、快速运动、人物交叉和不同机位下的表现；人物选择可重新指定，关键点本身仍需对照画面核实。

完成条件：明确哪些观测在约定拍摄条件下可用，哪些仍需要教练判断。显示骨架本身不视为完成技术纠错。

## 里程碑 4：自动判断少量教学问题

辅助手问题已有可解释的二维候选规则，其工程阈值尚待教练校准。继续收集同一问题的更多案例，包括存在问题、不存在问题、容易误判和无法判断的片段；必要时再训练专门模型。

完成条件：在未用于开发的球员视频上，与教练独立判断比较，报告误报、漏报和无法判断的情况。评估标准在测试前约定；不把相邻帧随机分到训练与测试集。

## 里程碑 5：检查练习后的变化

记录建议、练习内容和复拍视频，在尽量一致的任务条件下比较目标动作与击球表现。

完成条件：教练与球员能判断建议是否容易执行、目标问题是否改善。早期前后对比作为探索证据，不直接宣称因果或普遍有效。

## GitHub 与本地文件夹

- `D:\tennis` 是本地工作目录，程序与文档在这里编辑。
- Git 记录每次有意义的修改，便于回看和恢复。
- GitHub 托管推送上去的版本，供其他人查看与协作。
- 关联仓库后不会自动上传所有文件；修改经过提交和推送才会出现在 GitHub。
- `local/` 用于不公开的真实视频和教学记录。公开仓库从项目说明和空白模板起步。

仓库名称和第一版界面属于可调整的工程选择。教学规则与可行性结论须根据案例逐步确认。
