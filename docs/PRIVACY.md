# 视频隐私预处理

## 用户选择

脸部和环境分别可选，默认均为“不处理”。用户先在本机选择视频、查看处理结果，再决定是否导出。当前原型没有上传或分享接口，选择文件不会把视频传给服务器。

| 选项 | 当前行为 | 使用时需要知道 |
| --- | --- | --- |
| 脸部不处理 | 保持原始画面 | 导出仍会转为静音 WebM |
| 脸部遮盖 | 用户拖动画出一个或多个不透明固定区域 | 不是自动识别，也不跟踪头部；应覆盖所需时段的移动范围 |
| 环境不处理 | 保持背景 | 场地线索仍可见 |
| 环境像素化 | 用户框出保留区域，框外像素化 | 不是人体分割；框内背景仍可见，框外的球也可能变模糊 |

已开启处理却未画选区时不能导出。导出不会带上编辑边框。新文件使用 `-privacy-silent.webm` 后缀，不覆盖原片；完成后需点击下载保存。

## 为什么放在本机做

当前流程为：本机文件 → 浏览器内存中的视频 → 处理画布 → 本机下载。

- Python 服务只提供三个固定网页文件，监听 `127.0.0.1`，不开放仓库目录或 `local/`。
- 网页不使用外部字体、CDN、分析统计、上传接口或第三方推理服务。
- 不在浏览器持久化存储中保存视频。关闭页面释放该页面的处理状态；用户下载的文件会留在选择的保存位置。
- 服务设置内容安全策略，限制页面外联。此限制用于当前静态工具，不能作为未来加入其他功能后的自动保证。
- 原视频中的音轨不被加入导出，避免把声音一起分享。浏览器重新编码画布，不复制原始文件的附加元数据；这不等于完整匿名化，衣着、身形和场地仍可能具有辨识度。

未来若增加远程分析，应先明确展示待上传的版本、保留期限和删除入口，并只上传用户确认的文件。当前没有这样的远程流程。

## 与教学分析的关系

隐私处理不能制造本来不可观察的证据。遮住眼睛后，视线相关项目应显示“无法判断”，不能按未达标计分。背景处理应尽量保留完整身体、球拍、球路和必要的地面参照。

将来可以先在本机分析原片，再另行生成用于分享的打码版本；这是后续设计方向，当前尚未实现。当前只提供隐私预处理与人工视频复盘。

## 当前导出限制

- 依赖浏览器能够解码输入视频并支持 Canvas 与 MediaRecorder；建议近期版本的 Edge 或 Chrome，其他浏览器需实际验证。
- 按正常播放速度实时录制，耗时约等于视频长度；保持页面前台，转入后台会取消本次导出。
- 导出期间锁定编辑，允许取消。大文件会占用内存，建议先使用短片段。
- 保持输入画面尺寸，目标录制帧率 30 fps；实际帧率取决于设备。输出是重新编码的视频，不承诺逐帧无损或保留高帧率慢动作。
- 手动固定框适合验证流程，运动过程中可能漏遮。应完整检查最终副本，不能仅凭开头一帧确认整段都已覆盖。

## 开发依据

浏览器接口采用 [Canvas captureStream](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/captureStream) 和 [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)。浏览器测试用合成视频检查遮盖、区域保留、静音导出、取消与网络请求；本地服务另有私有路径不可访问的检查。
