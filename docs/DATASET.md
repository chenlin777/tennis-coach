# 教练标注数据集

第一步是收集一小批你愿意认真判断的正手视频，把“看到了什么、为什么这样判断、先改什么”记下来。先用 **20–30 个片段**校准规则，再按缺少的动作、机位和训练场景补充。数量不是完成标准；能追溯来源、看清关键动作、保留你的判断依据，才有助于后面的软件学习。

## 文件放在哪里

```text
local/
  videos/
    raw/          原视频，保留原样
    clips/        从原视频剪出的短片
    redacted/     短片的打码副本
  dataset/
    clips.csv     片段索引
    items/        工具生成的片段溯源记录
    labels/       每个短片的教练标签与独立的助手初标
    assistant-reviews/ 助手初标原稿与证据记录
    review.html   本地复看页（由工具生成）
```

`local/` 已被 Git 忽略，不随代码推送到 GitHub。打码文件也留在本机；打码不自动意味着可以公开。原视频、短片和打码副本是同一来源的不同版本，不能算成三个独立样本。

每个原视频有一个 `source_id`，每个短片有一个 `clip_id`。短片记录原片路径及原片中的开始、结束时间；打码版沿用短片的 `clip_id`，另外记录文件路径。以后修改标签时，仍能找到当时看的视频。

## 片段多长合适

**默认约 15 秒，通常 10–20 秒。** 一个片段可以包含多次正手，方便观察连续动作和调整。剪辑边界尽量放在击球之间，保留准备、击球、随挥和恢复，不为凑整秒而截断一次动作。先自动分段也可以，但需要人工检查边界。

50 秒的视频可以先均分成三段，每段约 16–17 秒，避免留下特别短的尾段。脚本按时长切分，**不会识别击球动作**，生成的片段边界都标为待检查；你检查后可以重新选择起止时间。后续需要精细分析时，再在短片内标出每次击球的起止时间，不必现在就把每一拍拆成单独文件。

剪辑示例（在项目文件夹中运行）：

首次双击 `setup-data.cmd` 安装依赖。日常可以直接把一个视频拖到 `prepare-clips.cmd`，然后双击 `start-dataset.cmd` 查看结果，无需输入命令。

```powershell
.\.venv\Scripts\python.exe scripts/prepare_clips.py --input local/videos/wall_practice.mp4
```

默认目标时长 15 秒，范围 10–20 秒。工具将原片导入 `raw/`，保留输入文件不动，再输出短片、索引和未标注的标签文件。短片放在 `clips/<经过文件名处理的source_id>/`，标签放在 `local/dataset/labels/`。可以重复 `--input` 选择多个文件；批量扫描目录限定在 `raw/` 内，避免把派生短片再次当原片导入。`--help` 提供完整参数。

不足 10 秒的源视频或指定窗口仍会保留，并在溯源记录中标记 `outside_duration_target`，不会补帧凑时长。剪辑保持原播放节奏，重新编码为 H.264 MP4，并保留存在的声音；静音由隐私导出步骤负责。源文件没有可读取时长时会明确报错，不猜测时长。每次重跑检查已有片段的哈希，不覆盖已写的人工标签。

如果希望只处理单个原片的某个时间窗口，例如第 10 秒至第 40 秒：

```powershell
.\.venv\Scripts\python.exe scripts/prepare_clips.py --input local/videos/wall_practice.mp4 --start 10 --end 40
```

当前隐私编辑器导出的副本另存到 `redacted/`，并在标签里记录 `redacted_path`。如果隐私处理遮住了分析所需细节，记录你实际标注的是原片、短片还是打码版。

## 不同机位可以一起收

现在不必只收一种机位，但每段从一开始就记下这些信息。看不清的内容填“未知”，不要根据示范者身份猜测动作好坏。

| 信息 | 可以怎样记录 |
| --- | --- |
| 机位 | 正面、背面、持拍侧、非持拍侧、斜侧、机位变化、未知 |
| 画面完整性 | 全身、头眼、辅助手、球拍、球是否可见；分别记清楚、部分可见、不可见或未知 |
| 视频处理 | 正常速度、慢放、变速或未知；是否有镜头切换、重复回放 |
| 训练场景 | 打墙、定点喂球、对拉、比赛、其他或未知 |
| 惯用手 | 右手、左手或未知 |
| 训练意图 | 例如“减少移动，把墙的回球控制在身体周围”；不知道就留空 |

近景可以帮助看辅助手，侧面通常便于记录前后关系，但能否判断仍以这个片段的可见内容为准。不同角度下无法判断的项目留空或标为“无法判断”，不要补出画面里没有的信息。慢放和剪辑信息也要保留，后续不能直接把播放速度当作实际动作速度。

## 怎样留下你的教学思考

剪辑工具会按 [标签模板](../templates/clip-label.json) 为每段生成一份标签，保存在 `local/dataset/labels/`。现在不要求你直接编辑 JSON：可以告诉助手“哪段视频、什么时间、看到了什么、怎么改”，由助手按你的口述整理。经授权，助手也可以按你的规则查看视频、填写带时间证据的初标。初标存入独立的 `assistant_review` 字段，教练的 `review` 保持原样；未由你确认时仍是 `unreviewed`。下载、剪辑本身不会产生动作好坏判断。

双击 `start-dataset.cmd` 可查看初标与教练判断，展开每一项并点击时间定位，也可半速播放、只看初标中有改进建议的片段。此页不会保存在线编辑。查看方式、取样范围和不可判断的原因一起保留，具体规则与导入见 [助手初标说明](ASSISTANT_REVIEW.md)。

整体判断由你选择：**好、需改进、无法判断、依情境**。一个片段可能同时有优点和要改的地方，所以还要按项目留下具体观察，不把整个片段的“好”直接套给其中每一拍。

| 教学项目 | 记录重点 |
| --- | --- |
| 眼睛跟球 | 头眼和球是否看得清；头部方向不能直接证明眼睛一直盯球。眼部被遮盖时，这项记为无法判断。 |
| 辅助手 | 是否举起指向球；何时开始向身体后方拉；与你说的“肘击”的动作提示有什么联系。 |
| 击球点 | 击球瞬间相对身体的位置；看不清接触瞬间或缺少尺度时，不填写猜测的厘米距离。 |
| 随挥 | 击球后持拍手和肩膀如何运动；完整过程是否入镜。 |
| 屈膝与重心 | 看得到的膝部屈伸、身体高度变化，以及你认为是否适合当时训练任务。 |
| 移动与击球位置 | 来球是否受迫、是否调整到合适位置；先结合训练目标判断。 |

每一条观察都记录：**短片内的时间 → 可见事实 → 你的解释 → 改进优先级 → 教学建议**。同一项目可以添加多条观察。时间使用短片内的秒数，从 0 开始；对应原片时间等于短片开始时间加这个数。

例如你描述的打墙练习，“尽量不移动”是训练意图，不能单凭移动少就标为问题；如果某一球确实受迫，需要另记这一拍的时间和判断依据。你已经指出屈膝较少，也应保留“打墙场景下可以接受”的情境说明。模板没有预填这些为视频事实，仍等你查看片段后确认。

## 如何扩充而不把数据弄混

第一批可以覆盖不同机位、动作熟练度和训练场景，同时保留“看不清、无法判断”的例子。你审完这批后，检查哪些判断反复拿不准，补充定义或拍摄要求，再有针对性地找更多素材。无需一开始硬凑同样数量的好与不好。

记录人物代号 `person_id`、拍摄场次 `session_id` 和重复来源组 `source_group_id`；不需要姓名，不知道就留空。重复来源组用来关联跨平台转载、不同长度剪辑等同一内容。文件哈希只能发现相同文件，无法排除重新压缩或裁剪后的转载，仍需人工核对。

以后划分训练集和测试集时，同一人、同一次拍摄、同一原片及其转载/派生片段都应放在同一组，不能把相邻短片随机分到两边。一个人跨场次出现、一个转载关联多个来源时，也要把这些关联一起考虑。人物身份未知时只能按已知来源分组，不能声称测试人物完全独立。目前先收集和标注，不提前分配训练/测试用途。

## 来源和公开范围

每个来源保留平台、原始链接、作者显示名、获取日期及授权说明；本机自录也记录为自录。获取是否成功与是否允许再分发分别记录：能下载到的视频，不应因此被写成“已获授权”。

代码的开源许可与视频素材的许可分开。外部素材先作为本机候选片段；是否可公开原片、打码版、标签或用于训练，分别根据已经取得的许可记录为允许、不允许或未知，并保存说明或证据位置。涉及出镜者的同意单独记录。未知保持未知，不在公开仓库里复制视频或含个人信息的标签。来源变化或后来撤回授权时，也可以通过 `source_id` 找到对应派生文件。
